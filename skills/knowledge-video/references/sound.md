# 声音选择与试听

## 音乐驱动模式

先锁定音乐与截取范围，按工程 docs/MUSIC-WORKFLOW.md 运行 music:analyze，保存 music-analysis.json；用 music:review 核对普通拍、重拍、半速/倍速、拍号和首拍，保存独立 music-overrides.json。变速音乐使用完整手工拍表。confidence 是相关强度，重拍默认只是 4/4 假设；第二阶段局部节奏、段落与调性窗口也只给候选，乐器仍需人工标注。

配置 project.files.musicSync，建立事件、源拍序号、动作落点、音效和版本对应关系。截取、速度和偏移统一映射为成片帧；音效有起音时配置 soundOffset 与负事件偏移。运行 music:check 和 check 后先渲染 0–10 秒，核对节拍漂移、音画同步、音色冲突、密度、尾音及阅读时间。技术通过不代表已试听。

收到反馈后分段推进；换音乐或改拍表后审查受影响事件，不批量更新版本绕过检查，不覆盖已认可输出。tone/kick 仅作简单候选；真实乐器质感使用有来源素材并混合试听。

## 第二阶段编辑与验收

详读工程 docs/MUSIC-PHASE2.md。用时间轴编辑逐拍表和段落；变速、停顿和弱节奏优先检查不确定区间。导出提案后用 music:impact 查看动作、字幕、音效与认可片段的变化，用 music:apply 应用一致且有效的候选。不要用手改 revision 代替影响预览。

用 music:status / music:accept 保存每段 pending、needs-changes、approved 和版本依据；实际观看试听后才标记 listened。已认可片段变更后显示 needs-review，未受影响片段保留状态。

用 sound 标签登记乐器、MIDI 音高、可听起点、峰后有效尾音、LUFS 与真峰值；music:sound 输出候选，不自动写资产索引。music:palette 根据标签和当前调性窗口推荐已登记素材，提供原音与固定音乐混合试听；uncertain 结果以试听为准。

自动混音报告使用 FFmpeg 测量 LUFS/真峰值，比较动作窗口内合并音效与配乐的 RMS；这不是单个重叠音效的响度，也不代表可辨认性通过。duckingCandidates 不自动应用，选择后局部 A/B 比较。最终视频编码成功后另查 encoded-audio-quality.json。

## 选材顺序

先明确整段内容的节奏和情绪，再选择能形成连续配乐的素材。音乐不必固定一种类型；判断它是否留得出阅读和理解空间，以及重要段落能否自然衔接。

音效从具体内容事件出发：对象出现、机制启动、关系改变、动作完成、结论强调。开始和结束可以有不同声音，不绑定固定素材或升降调公式。它们应在当前上下文中容易辨认，又不破坏整体质感。

## 从动作设计声音

在已有分镜或音效配置中写清“什么在变、声音提醒哪一刻、素材实际可听起点、有效尾音、当前配乐下要验证什么”。启动、意义变化和落定是不同候选落点，一次动作不必把三处全部配满。标签由报价说明变成比较依据时，声音帮助观众察觉身份改变；不因为标签移动就自动配持续滑动声。

声音文件的0秒可能有静音或缓慢起音。先找素材可听起点，再用命名事件、sourceIn或事件偏移对齐画面，随后在混音中核对；波形峰值不一定是听到动作开始的时刻。画面与声音共享事件参数，避免一处改了动画，另一处还保留旧秒数。一次完整的“刷”声与多次重复短声在节奏上不同，不能仅通过拼接多段把长度补齐。

先判断声音是否符合讲解的情绪与材质，再选音色。纸签交接、铅笔划线、界面确认可以提供候选方向，但都不是固定答案；弹跳、金属亮音、长混响也不能因为醒目就通用。用户反馈“空旷”时检查混响与尾音，“死硬”时检查起落、动作节奏和截断，“重复”时检查附近动作的声音功能是否重叠。短而近的声音适合部分情境，仍需结合整段配乐判断。

三个依次出现的对象，若三个出现时刻都承担信息，可以逐个配轻提示；若表达的是整体归组，可以用一次有整体落点的声音。依照意义和密度选择，不能机械认定三个对象一定三响。删除不必要音层、只留开始或结束，都可以是完整方案。

保留用户已经认可的配乐和声音质感。比较候选时优先只改素材、时刻、包络或音量中的一个维度；先听含前后动作的局部混音，再用分轨定位问题。短素材单独听合适，不代表放进连续配乐后仍协调。过程声是否持续、音量是否渐强，应服务当时的变化，不把一次反馈写成所有项目的固定公式。

素材优先考虑用户指定素材和本项目可用素材；按需要读取素材索引。素材不足时可以先制作画面，做无配乐预览或制作少量简单程序音效。简单正弦提示音和鼓点不是完整 AI 配乐；未接入的生成服务不作为已具备的能力。

## 新版音频配置需要表达的内容

| 字段 | 如何填写 |
| --- | --- |
| role | music/start/end/transition/process/accent，描述用途而不是音色 |
| purpose | 此声音帮助解释哪个内容变化；启用音效时必填 |
| musicFit | 当前候选与配乐的搭配判断或明确的待试听问题，不伪造已确认结论 |
| source、sourceIn、sourceOut | 新工程使用 asset:素材id 与原素材秒数，先在本期或公共素材索引登记 |
| at | 成片秒数或命名事件引用 |
| gain、buses | 单项及角色的相对音量；不能只凭峰值判断可听见 |
| enabled | process 需显式 true；不需要的声音可以关闭，而无需删除候选 |
| ducking | 必要时在事件附近降低 music 音量并恢复，不改节奏和位置 |

详细字段与合法范围读工程自身的音频工作流文档。新建骨架的默认方案为空；example 中的候选未启用。把路径填对不代表音效已经选好。

配乐避让的 at 是达到目标音量的时刻，attack 向前展开，hold/release 向后展开。重叠避让取最强一次；不为每个小动作都安排明显的音乐起伏。

## 过程音的判断

普通位置移动不必有过程音。持续加速、倒计时、压力积累等变化可能受益于声音，但仍需与配乐一同听。

过程声可以连续也可以分段；选择依据是表达，不是“连续一定更好”。持续有音高的声部可能形成另一条旋律，细碎音点可能像额外节拍，宽频噪声可能有摩擦感。出现冲突时先检查是否需要该层，再调整音色、频段、密度、时长和音量。

对“要连贯”的反馈，判断用户是在说音乐衔接、动作声音还是整体节奏。可以用统一声学质感、自然收尾和合理留白建立连贯感，不自动增加一条持续声部。

## 处理常见听感反馈

| 反馈 | 先检查什么 | 可选调整 |
| --- | --- | --- |
| 结束音听不见 | 事件是否正确、混音中是否存在、是否被配乐掩盖、衰减是否过快 | 调整音色和有效时长、适量增益，必要时配乐短暂避让 |
| 过程声吵或混乱 | 是否形成额外旋律/节拍，持续声是否真的解释内容 | 减少或关闭该层，选更合适素材，再考虑音量 |
| 转场不舒服 | 与画面交接是否同步、尾音是否拖到下一动作 | 改触发位置、素材或收尾，不只加新效果 |
| 开始与结束不像一套 | 声学质感、空间感和响度是否协调，能否听出功能 | 保留用户认可部分，选择适配的变体；允许不同素材 |

用户已认可的部分在迭代中保持可追踪。需要比较时，优先一次改变一个影响听感的维度，避免同时改画面、配乐速度和全部音色导致无法判断原因。

## 试听与证据

先按实际音量听完整混音，必要时切到配乐或音效定位冲突，再回到混音判断。A/B 保持相同片段和播放音量；候选方案先写另一份音频 JSON，不直接覆盖现用配置。

Remotion 审片页同时显示画面；切换候选保持位置。当前工具的峰值、RMS、采样和浏览器检查只能验证技术结果。若当前执行环境不能真正听到音频，应核对技术证据并交付可播放片段，请用户给听感反馈；不要声称亲自试听过。此前的源码波形检查也不能证明某个音色好听。

试听页的 listened 表示检查项被勾选，不代表接受方案。实际问题和选择写进备注，下载记录后按需归档到本期。没有必要为了得到一个勾选而阻止其他已授权的内容、画面和导出工作。

对外发布所需素材许可依据用户素材来源和实际用途确认；本地生成示例不等于素材可再分发。不要自动发布或把原音乐打包进 Skill。
