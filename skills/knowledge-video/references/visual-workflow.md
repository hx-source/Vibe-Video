# 从规格到代表片段验证

## 制作顺序

1. 先确定分辨率、比例、帧率、预计时长、字幕和配音要求。沿用已确认的规格；默认 hd1080，参考片规格可选 hd720。当前只支持 16:9、中文字幕、不配音；其他要求需明确实现后再承诺。
2. 选定主题，明确受众、一个核心问题及观众应理解的结论。根据主题寻找并核实内容，优先可靠原始资料；记录来源、案例、简化和争议边界，不能把参考片当作事实依据。
3. 分析必要前提、易误解点和讲解顺序。将每个知识点对应到对象、关系、状态及可观察变化，写入分镜。不要用频繁弹出的文字替代解释。
4. 默认提出三种可实现的视觉方向。用同一段实际内容、同一时刻和相同规格渲染关键静帧；说明每种方案为什么适合本期内容、怎样运动、哪些已有实现、哪些需要新增场景。
5. 展示具体示例后由用户选择。允许“选一个”“保留某方案但调整配色、字号、人物或背景”“三种都换掉”。已有明确参考、指定方案或此前认可的风格时直接沿用，不重复要求选择。
6. 风格选定后细化场景与分镜。音乐卡点任务先选定固定音乐、分析并校正节拍，再确定动作落点；保留字幕阅读和机制解释所需时间。概念图不能代替可渲染实现。
7. 选择最能代表成片效果的连续十秒：包含核心机制、至少一次有意义的状态变化及主要视觉元素。可以位于全片中段；记录全片范围、比较静帧时刻和选择理由。不把十秒都用作标题，不通过整体加速塞进更多知识。
8. 交付带中文字幕、固定音乐与关键动作音效的十秒样片。用户实际观看、试听并认可后再扩展全片。样片认可只覆盖该版本和范围，不替代未观看段落的验收。

## 工程调用

完整接口以工程 docs/VISUAL-WORKFLOW.md 为准。创建项目时使用 `new --preset hd720` 或 `--preset hd1080`；先填充 facts、storyboard、captions 和音频计划，再运行 `design:init`，不要把占位资料当作已完成研究。

使用 `design:brief --proposal production-proposal.json` 写入规格、主题、来源、讲解结构、场景变化及代表片段。手工指定范围时同时给出 from、to、stillTime 和 reason；十秒范围不能越界。

用 `design:preview` 生成同内容三方案比较页。当前夜空叙事、清晰图解、纸本手绘在 moon-match 场景中支持背景、人物形式、线条和字号切换；cards、sequence、cycle、anchoring 只有配色和公共版式的部分适配。照实说明能力，不宣称所有主题都有完整风格库。

- 用户选择后运行 `design:select --candidate <id>`，写入本轮选择及用户原话。
- 局部调整使用 `design:revise --candidate <id> --proposal visual-patch.json`，只修改指定参数，再预览。保留认可的其他部分；需要混合方案时明确哪些参数继承、哪些覆盖。
- 换一批时先按内容设计新的三组 candidates，再用 `design:propose --proposal candidates-proposal.json` 开新轮。更换须有实际视觉差异，不能只改名称；不删除旧轮次或把新方案自动标为用户选择。
- 用 `design:sample` 生成指定的代表片段，沿用全片动作和音乐时钟。不要为抽取中段而把事件或配乐重置到零。
- 收到用户对该样片的实际观看和试听反馈后，才用 `design:accept --manifest ... --state approved --viewed true --listened true` 记录认可。测试、静帧预览、旧输出和技术检查均不能代填。
- 用 `design:status` 查看 pending、needs-changes、approved、needs-review。视觉、内容、音乐、素材或范围变化会使旧认可失效；重新交付受影响样片，保留历史输出。

旧项目没有启用 visualPlan/productionPlan 时保持原行为；不要为了采用新流程静默改变已认可成片。样片只用于确认制作方向，全片仍需按内容和音乐段落逐段审阅。
